# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Surface: one fixed **720×480** frameless, non-activating NSPanel hosting an opaque WKWebView (`frontend/src/App.svelte` and children). No other windows in this phase. Feel: Spotlight/Raycast. Minimal chrome, keyboard first, animated grid.

Sources: 02-CONTEXT.md (locked: layout, keys/first run, search & keyboard), FEATURES.md (KB-1..KB-9, attribution section 5, first run section 6), STACK.md (Svelte 5 + Vite 8 + TS, `@tanstack/svelte-virtual` row virtualization, opaque webview), `internal/shell/shell.go` (panel options), GIPHY attribution-marks zip (inspected 2026-10-17), Klipy attribution doc. Items marked **[default]** are researcher defaults not covered upstream.

## Design System

| Property | Value |
|----------|-------|
| Tool | none. shadcn is React-only. The UI is one panel with about 8 components, so a Svelte component library (shadcn-svelte, bits-ui) costs more than it saves **[default]** |
| Preset | not applicable |
| Component library | none (hand-written Svelte 5 components plus CSS custom properties) |
| Icon library | none. 5 inline SVG icons, 16×16 viewBox, `stroke="currentColor"` stroke-width 1.5: magnifier, spinner, check, external-arrow (↗), alert-circle |
| Font | System UI: `-apple-system, BlinkMacSystemFont, system-ui, sans-serif` (SF Pro). Key field only: `ui-monospace, "SF Mono", Menlo, monospace`. Do not load `public/Inter-Medium.ttf` |
| Styling | One global token file `frontend/src/app.css`, imported from `main.ts`, plus component-scoped `<style>`. `frontend/public/style.css` is Wails template residue and is not linked from `index.html`. Do not link it |
| Theme | `:root { color-scheme: light dark; }`. Light tokens are the default, dark tokens go in `@media (prefers-color-scheme: dark)`. No manual toggle |
| Window shape | Corners come from the native AppKit frame (`Mac.CornerType` stays at its Rounded default with `CornerRadius: 0`; see `usesNativeMacFramelessFrame`). The CSS root gets **no** `border-radius` and fills the window edge to edge. No backdrop or translucency (that would need `private_mac_apis`) |

## Layout Contract (720×480, fixed)

```
┌──────────────────────────────────────────────────────────────── 720 ─┐
│ [⌕]  Search GIPHY                                         [spinner] │  Search bar   48px
├──────────────────────────────────────────────────────────────────────┤  (1px hairline, inside the 48px)
│ (GIPHY ⌘1) (Clips ⌘2) (Klipy ⌘3) (Finer Gifs ⌘4)                     │  Provider tabs 36px
├──────────────────────────────────────────────────────────────────────┤  (1px hairline, inside the 36px)
│ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐                                  │
│ │ GIF  │ │ GIF  │ │ GIF  │ │ GIF  │   4 columns, tiles 166×144       │  Content area 364px
│ └──────┘ └──────┘ └──────┘ └──────┘   (grid / setup card /           │  (scrolls vertically)
│ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐    empty / error / Clips card)   │
│ └──────┘ └──────┘ └──────┘ └──────┘                                  │
│ ┌──────┐ ┌──────┐ ...  (partial third row shows there is more)       │
├──────────────────────────────────────────────────────────────────────┤  (1px hairline, inside the 32px)
│ [POWERED BY GIPHY]     selected title / status…          ↵ Copy ⌘↵ Paste │  Footer 32px
└──────────────────────────────────────────────────────────────────────┘
```

| Region | Height | Horizontal padding | Contents |
|--------|--------|--------------------|----------|
| Search bar | 48px (`box-sizing: border-box`, bottom hairline included) | 16px | 16px magnifier icon (`--text-secondary`), 8px gap, input (fills the row), 16px loading spinner pinned right when a request is in flight |
| Provider tabs | 36px (bottom hairline included) | 8px | 4 tab pills, 4px gap, vertically centered. Each pill is 28px tall with 8px horizontal padding and contains the label plus an 8px gap plus a shortcut hint. Row padding 8px + pill padding 8px puts the first label on the same 16px column as the magnifier icon and the grid's left edge |
| Content area | 364px | grid: 16px left/right padding, 16px top and bottom padding, 8px gap | One of: result grid, setup card, state message, Clips card |
| Footer | 32px (top hairline included) | 16px | Left: attribution. Center (flex 1, 16px gap each side): selected-GIF title or status message. Right: key hints |

**Tile geometry (fixed 4 columns, never computed from width):** tile width = (720 − 2×16 − 3×8) / 4 = **166px**, tile height **144px**, row stride 152px (144 + 8 gap). Visible rows = (364 − 16 top padding) / 152 = **2.3 rows**. The partial third row is intentional and signals that the grid scrolls.

- The grid is virtualized by **row** (`@tanstack/svelte-virtual`, `estimateSize: () => 152`, overscan 2 rows, `paddingStart: 16`, `paddingEnd: 16`, `scrollPaddingStart: 16`, `scrollPaddingEnd: 16`), so only mounted rows decode GIFs (KB-9).
- Tile: `border-radius: 8px`, background `--surface`. `<img>` uses `object-fit: contain`, centered, with `decoding="async"` and `draggable="false"`. Use `contain`, not `cover`: Finer Gifs clips carry captions at the bottom edge, and cropping would hide them. Drag-out is v2 (DIFF-01).
- The grid uses the provider's small preview rendition only (never the original).
- No title text under tiles. The selected GIF's title shows in the footer center **[default]**.
- Rows are top-aligned and left-aligned. One result renders as a single tile in the top-left, never centered.
- The selection ring is drawn with `outline: 2px solid var(--accent); outline-offset: 2px`, so it extends 4px beyond the tile. That fits inside the 8px gap and the 16px outer padding. The 16px scroll padding is larger than the 4px ring extent, so a scrolled-to tile's ring stays fully inside the viewport and the scroll container never clips it.
- Hover: tile background changes to `--surface-active`. Hover never moves the selection.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between tab pills, icon-to-text gap inside buttons, gap between numbered steps |
| sm | 8px | Grid gap, search icon-to-input gap, tab-row horizontal padding, tab-pill horizontal padding, gap from tab label to shortcut hint, stack gap between card body lines, key field to `Save Key` gap |
| md | 16px | Search bar and footer horizontal padding, grid outer padding (left, right, top, bottom), virtualizer scroll padding, button horizontal padding, footer inter-zone gap, gap between card blocks (heading → body → field row → links row) |
| lg | 24px | Setup / state card inner padding |
| xl | 32px | Minimum top offset for centered state messages in the content area |
| 2xl | 48px | Search bar height (layout constant, not a gap) |

Exceptions (not spacing, listed so the checker does not flag them):
- 1px hairline separators. 2px selection / focus ring with 2px offset.
- Computed tile width of 166px (derived from the 16px padding and 8px gap above, not a spacing value). Tile height 144px.
- Component heights: buttons and the key field are 32px, tab pills 28px, tab row 36px, footer 32px, loading-more / end-of-results row 48px, inline message slot 16px.
- Layout widths: setup card 456px, state copy `max-width` 432px.
- Corner radii (not spacing): buttons and key field 6px, tiles 8px, setup card 12px.
- Attribution image is 16px tall with auto width (about 144px).

No 12px spacing value exists anywhere in this contract. Every padding, margin, and gap is 4, 8, 16, 24, or 32px.

## Typography

Exactly 4 sizes and 2 weights (400 regular, 600 semibold).

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Label | 12px | 400 | 1.33 (16px) | Footer title/status, footer key hints, tab shortcut hints (`⌘1`), Klipy/Finer Gifs attribution text, inline field errors, end-of-results row, rate-limit retry time |
| Body | 14px | 400 (600 for buttons) | 1.5 (21px) | Tab labels (always 400, so the active tab does not change width), card and state body copy, numbered steps, key field (monospace), button labels (600) |
| Heading | 18px | 600 | 1.2 (22px) | Setup card title, empty/error/Clips state headings |
| Display | 22px | 400 | 1.2 (26px) | Search input text and placeholder |

Scale steps are 12 → 14 → 18 → 22. Heading and Display differ by both size (4px) and weight (600 vs 400): Heading is the bold anchor inside a card, Display is the large light input text at the top of the panel. The 26px Display line box sits in the 48px search bar, vertically centered by flexbox (`align-items: center`), not by vertical padding.

Text never goes below 12px. Long text rules: the footer title/status is one line with an ellipsis (`white-space: nowrap; overflow: hidden; text-overflow: ellipsis`). Card and state copy wraps at `max-width: 432px`. The search input scrolls horizontally (native behavior).

**Accent reserved for (exhaustive):**
1. Selected-tile ring (2px outline)
2. Primary button fill (via `--accent-fill`): "Save Key" (S1), "Add GIPHY Key" (C1), and "Email clips@giphy.com ↗" (C2, an `<a>` styled as a primary button; amended in 03-07, shipped 02-06 copy)
3. Text links (`--accent` text, underline on hover): "Get a free key ↗" (S1) and the inline "Try Again" link in the end row (S12a / E6)
4. `:focus-visible` ring on buttons, links, and the key field (2px outline, 2px offset)
5. Search input and key field caret (`caret-color`)

Accent is **not** used for tabs (the active tab is a `--surface-active` pill with `--text`), spinners (`--text-secondary`), hover, or the attribution.

## Provider Tabs Contract

| Slot | Label | Shortcut | Search placeholder (exact) | Footer attribution |
|------|-------|----------|----------------------------|--------------------|
| 1 | GIPHY | ⌘1 | `Search GIPHY` | Official GIPHY mark (image) |
| 2 | Clips | ⌘2 | `Search GIPHY Clips` | Official GIPHY mark (image) |
| 3 | Klipy | ⌘3 | `Search KLIPY` (**exact, compliance-required**) | Text `Powered by KLIPY` |
| 4 | Finer Gifs | ⌘4 | `Search The Finer Gifs Club` | Text `GIFs from The Finer Gifs Club` |

- Slots are fixed, so ⌘1–⌘4 always map to the same provider.
- **Clips slot when unavailable** (Clips probe failed, or no GIPHY key yet): the pill still renders in slot 2 with label "Clips" in `--text-tertiary`, `aria-disabled="true"`, and `title` set to the short explanation. Choosing it (⌘2 or click) shows the Clips card (Copywriting rows C1/C2) in the content area instead of a grid. While the probe is pending, the slot looks the same and choosing it shows the loading skeleton.
- Active tab: `--surface-active` pill with a `--text` label. Inactive: transparent pill with a `--text-secondary` label. The shortcut hint is always `--text-tertiary`, 12px.
- The tabs are mouse-clickable but are **not** in the Tab-key order (keyboard users use ⌘1–⌘4). Clicking a tab returns focus to the search input.
- The last-used provider is persisted. If the persisted provider is Clips and Clips is unavailable at launch, open on GIPHY.
- Switching providers keeps the query text. With 2 or more characters, it searches the new provider immediately (no debounce). Otherwise it shows that provider's trending results (cached, 10 min TTL).

## Interaction Contract

### Focus model (KB-1)
- When the panel shows (`panel:show`), the search input gets focus and its text is selected, so typing replaces the query (kept from Phase 1). The query and results persist between shows.
- Typing always goes to the search input. The grid never takes DOM focus. The input carries `role="combobox"`, `aria-controls` pointing at the grid, and `aria-activedescendant` set to the selected tile's id. The grid has `role="listbox"` and tiles have `role="option"`, `aria-selected`, and `aria-label` = GIF title (fallback "GIF {n}").
- **Exception:** while a setup card is showing, the search input is `disabled` (its placeholder stays visible) and the key field holds focus. The Tab key cycles key field → Save Key → Get a free key ↗ → Try Finer Gifs (no key).

### Keys

| Key | Behavior |
|-----|----------|
| Printable characters | Edit the query. Search fires **450 ms** after typing stops, with a minimum of 2 trimmed characters. Superseded requests are cancelled. 0–1 characters show trending (no request) |
| ← → | Move the selection by one tile, wrapping across rows. Clamped at the first and last tile. Applies even when the input has text (the caret does not move) |
| ↑ ↓ | Move by 4 (one row). ↓ from the last full row goes to the last tile. ↑ on the first row does nothing |
| ↵ | Copy the selected GIF as a file (see Copy flow). Ignored when `isComposing`, `keyCode === 229`, `repeat`, or a copy is in flight. When no tile is selected and an error state with "Try Again" is showing, ↵ runs Try Again |
| ⌘↵ | Paste the selected GIF into the previous app (Phase 1 primitive, now with the selected result). Same guards as ↵ |
| Esc | If the focused field (query or key field) is non-empty, clear it. Otherwise hide the panel. **Requires `HideOnEscape: false`** in `internal/shell/shell.go`; hiding moves to a bound Hide call from the webview. Today the native option hides on the first Esc |
| ⌘1–⌘4 | Switch provider (works from the key field too) |
| ⌘K | Bound and `preventDefault`. No-op, no UI, not advertised (the action menu ships in Phase 3) |
| Tab (grid mode) | `preventDefault`. Focus stays in the search input |

### Selection (KB-3, KB-4)
- On a new result set (new query or provider switch), the first tile is selected. When a page is appended, the selection is kept. Every selection change calls `scrollIntoView({ block: 'nearest' })` through the virtualizer's `scrollToIndex`.
- The next page loads when the selected index is within the last 2 rows (8 tiles) **or** a scroll sentinel after the last row enters the viewport. Page size is 24. Only one page request is in flight at a time.
- Mouse: a single click selects. A double click runs ↵ (Copy) **[default]**. The scroll wheel scrolls without moving the selection.

### Copy flow (↵)
1. In flight: the selected tile shows a 16px spinner centered on a `rgba(0,0,0,0.4)` overlay. The footer center shows `Copying…`. Further ↵ and ⌘↵ presses are ignored.
2. Success: the footer center shows the success check and `Copied — press ⌘V to paste` in `--success`. The panel hides **400 ms** later (a short confirmation that stays out of the way). Status clears on the next show.
3. Failure: the panel stays open. The footer center shows `--destructive` copy (row E7). Selection is unchanged.
4. Clips tile: no download. The footer shows row E8 and the panel stays open.

### Paste flow (⌘↵)
Phase 1 messages and behavior are kept, applied to the selected result. When `needsAccessibility` is set, the footer right zone swaps its hints for a secondary button `Enable Automatic Paste…`, which calls `RequestAccessibility`. A copied-but-not-pasted fallback message survives to the next show (Phase 1 `keepStatus`). Tray "Settings…" `panel:status` text also shows in the footer center.

### Footer center precedence
In-flight or result status (Copying…, Copied, copy error, key saved, `panel:status`), then the selected GIF's title, then empty. A transient status (`Key saved`, copy error) clears on the next keystroke or selection change.

### Motion
- Skeleton tiles pulse their opacity 1 → 0.6 → 1 over 1.2s ease-in-out. The spinner rotates at 0.8s linear. No other UI animation (no fades, no slides).
- `@media (prefers-reduced-motion: reduce)`: skeleton pulse off (static `--surface`). The spinner is replaced by a static 16px three-dot glyph, keeping its `aria-label="Loading"`. GIF tiles keep animating in this phase. Still renditions for reduced motion are deferred (see UI Considerations).

## Content-Area States

Exactly one state renders in the 364px content area. State messages are centered horizontally, sit at least 32px from the top, and use `max-width: 432px`, text-align center. Layout: 24px alert/check icon (when listed) → 8px → heading 18/600 → 8px → body 14/400 `--text-secondary` → 16px → button(s). Buttons are 32px tall with 16px horizontal padding, 14/600, radius 6px. Primary: `--accent-fill` with white text. Secondary: `--surface-active` with `--text`.

**Primary visual anchor per state (one focal point each):**
- Grid states (S3, S4, S5, S6, S9a, S12a): the selected tile and its 2px accent ring.
- No grid to select from, either because the query is empty and the provider has no trending list (S8) or because the first page is still loading (S2): the search input (22px Display text, accent caret), since typing is the next action.
- Setup card (S1, S1a, S1b, S13): the setup card, specifically the key field and the `Save Key` primary button (the only accent-filled element on screen).
- Message states (S7, S9, S10, S11, S12, C1, C2): the 18/600 heading, followed by the state's single button (`Try Again`, `Add GIPHY Key`, or `Email clips@giphy.com ↗`).

| ID | State | Trigger | Visual |
|----|-------|---------|--------|
| S1 | Setup card (GIPHY / Klipy) | Active provider needs a key and has none | `--surface` card, radius 12px, 24px padding, width 456px, centered, 24px from top. Contents top to bottom: heading, body, numbered steps (14px, 4px apart), field row (key field flex 1 + 8px gap + `Save Key` primary), 8px gap, inline message slot (16px tall, Label 12px text), links row (`Get a free key ↗` link on the left, `Try Finer Gifs (no key)` secondary button on the right). The inline message slot shows the matching row (K2–K4) in `--destructive` with a 12px alert icon. The field keeps its text, gets focus, and has its text selected. Editing clears the message |

| S5 | Loading more | Next page in flight | One extra 48px row after the last tile row with a 16px spinner centered |

| S10 | Network error | DNS, refused, or offline | Alert icon, rows E3, `Try Again` secondary button |
| S11 | Timeout | Request exceeded its timeout | Alert icon, rows E4, `Try Again` |
| S12 | Provider error | Non-2xx other than 401/403/429 | Alert icon, rows E5 (Finer Gifs: E5f), `Try Again` |
| S12a | Error while paging | Network, timeout, or provider error on page 2+ | Results stay. The 48px end row shows `Couldn't load more.` (12px `--text-secondary`), a 4px gap, then a `Try Again` text link (12px, `--accent`, accent list item 3) |
| S13 | Saved key rejected | 401/403 during search with a stored key | S1 setup card for that provider, with row K6 pre-filled in the inline message slot (`--destructive`). Saving a new key overwrites the Keychain entry **[default: avoids a dead end before Phase 4 Settings]** |

| C2 | Clips: key lacks access | Clips probe failed for a valid key | State message, rows C2. Primary `Email clips@giphy.com ↗` (a pre-addressed `mailto:`) is an `<a>` styled as a primary button (`--accent-fill`, white text). Secondary: `Back to GIPHY` |

Every error state is scoped to its own provider tab. Switching tabs shows the other provider's own state, so one failing provider never blocks the rest. Raw response bodies, URLs, and keys never render. Only the provider name and, for S12, the HTTP status code appear.
