# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This contract extends `02-UI-SPEC.md`. It does not redefine it.** Everything there still holds: the 720×480 panel, the search bar (48px), tabs row (36px), content area (364px) and footer (32px), the 166×144 tiles in 4 fixed columns, the 4/8/16/24/32 spacing scale, the 4 type sizes and 2 weights, the color tokens, the copy flow, and every S/E/K/C state. This document covers only what Phase 3 adds or changes. Where it amends a Phase 2 rule, the row says **Amends 02**.

Surface: still the single non-activating panel. Phase 3 adds 4 overlays and views inside it: the ⌘K action menu (a popover), the Details pane, Favorites and Recents tabs (sectioned grids), and the recent-search chip row. It also adds tile badges and footer toasts with an action. No new windows.

Sources: 03-CONTEXT.md (locked: action menu, favorites and recents, details and recent searches, files/Clips/square), 02-UI-SPEC.md (baseline tokens and conventions), 02-UI-REVIEW.md and `.planning/todos/pending/phase-2-ui-review-polish.md` (polish folded in below), the code as built (`frontend/src/app.css`, `App.svelte`, `components/*.svelte`, `lib/grid.ts`, `lib/providers.ts`), and `internal/provider/provider.go` (`Gif` carries only id, title, previewUrl, downloadUrl, isClip today). Items marked **[default]** are researcher choices that the upstream artifacts do not cover. Section "Open Questions" lists the ones the user should confirm.

### Tabs row (Amends 02 Provider Tabs Contract)

| Slot | Label | Shortcut | Search placeholder (exact) | Footer attribution |
|------|-------|----------|----------------------------|--------------------|
| 1–4 | unchanged (GIPHY, Clips, Klipy, Finer Gifs) | ⌘1–⌘4 | unchanged (`Search KLIPY` stays exact) | unchanged |
| 5 | star icon + `Favorites` | ⌘5 | `Search Favorites` | Follows the selected item's provider (see Library attribution) |
| 6 | `Recents` | ⌘6 | `Search Recents` | Follows the selected item's provider |

- Six pills fit in one row: about 580px of the 704px available. No scrolling, no wrapping.
- A divider separates the provider pills from the library pills: 1px wide, 16px tall, `--hairline`, vertically centered, with 4px margin on each side. Together with the 4px pill gap, that puts 8px of space on each side of the line.
- The Favorites star is the outline `star` icon at 12×12, `currentColor`, with 4px gap before the label. The tab's accessible name is `Favorites` (the icon is `aria-hidden`).
- Library pills use the same active/inactive styling as provider pills. They are not in the Tab-key order. Clicking one returns focus to the search input.
- **Persistence [default]:** only provider tabs (1–4) are persisted as the last tab across launches. Within one session, the current tab (library tabs included) is kept between panel shows, like the query and results.
- Switching to a library tab keeps the query text, which then acts as that tab's title filter (consistent with Phase 2's "switching keeps the query").

## Interaction Contract

### Keys (Amends 02 Keys table; Phase 2 rows not listed here are unchanged)

All shortcuts below call `preventDefault` when they act. "Item" means the selected tile in a provider grid or library grid, or the item shown in Details.

| Key | Context | Behavior |
|-----|---------|----------|
| ⌘K | Grid or Details with an item | Open the action menu. ⌘K again closes it. No item (empty, loading, message state, setup card) → no-op |
| ⌘5 / ⌘6 | Anywhere (also from the key field) | Switch to Favorites / Recents |
| ⌘⇧C | Item | Copy Link |
| ⌘⇧M | Item | Copy Markdown |
| ⌘O | Item with a page URL | Open in Browser. No page URL → no-op |
| ⌘S | Item | Download (GIF or MP4) |
| ⌘⇧F | Item | Toggle favorite |
| ⌘I | Item | Open Details. In Details, ⌘I closes it |
| ⌘⌫ | Library tab, item selected | Remove from Recents / Remove from Favorites. Captured even when the query has text (so it never deletes the filter text). Use Esc to clear the filter |
| ⌘⌫ | Provider tab, chip selected | Remove that recent search (no toast, no undo) |
| ⌘⌫ | Provider tab, tile selected | Not captured (native text editing in the search input) |
| ⌘Z | While an Undo toast is visible | Undo. Otherwise not captured (native undo in the input) |
| ⌘R | While the download toast is visible | Show in Finder **[default]** (Spotlight uses ⌘R for "show in Finder"). Otherwise captured and ignored (never reloads the webview) |
| ↵ / ⌘↵ | Grid, Details | Copy / Paste the item's file (GIF, or MP4 for Clips). Phase 2 guards apply |
| ↵ | Chip selected | Rerun that search: the query becomes the chip text, the search fires at once (no debounce), the chip row hides (the query is no longer empty), and the first result is selected |
| ↑ | Grid, first tile row, chip row visible | Move selection to the first chip **[default]**. Library tabs have no chips, so ↑ on the first row does nothing |
| ↓ | Chip selected | Return to the grid's first tile. With no grid (S8 or a message state), does nothing |
| ↓ | No grid, chip row visible (S8 or message state), nothing selected | Select the first chip |
| ← → | Chip selected | Move between chips, clamped at both ends |
| ← → | Details | Show the previous / next item (selection moves in the underlying grid, clamped). **[default]** |
| Printable characters | Chip selected | Typing goes to the input as usual. The chip selection clears, and the chip row hides once the query is non-empty |
| Printable characters | Details open | Close Details, then edit the query |
| Esc | Action menu open | Close the menu (one press, even with filter text: **locked**). Selection and query unchanged. Focus returns to the search input |
| Esc | Details open | Close Details. Selection kept |
| Esc | Otherwise | Phase 2 rule: clear the query if non-empty, else hide |

Library-tab grid movement: the selection index runs through all items in section order. ← → step through that order, crossing section boundaries. ↑ ↓ move by row within a section. ↓ from a section's last row goes to the same column in the next section's first row, clamped to that row's last tile. ↑ from a section's first row goes to the same column in the previous section's last row, clamped. Implement as a pure function in `lib/grid.ts` with node tests.

### Action menu behavior

- Opening: DOM focus moves to the filter field. The first row is highlighted. The underlying grid selection is unchanged. The filter field is a `role="combobox"` with `aria-controls` pointing at the list and `aria-activedescendant` pointing at the highlighted row. The popover is `role="dialog"` with `aria-label="Actions"`. The list is `role="listbox"`, rows are `role="option"` with `aria-keyshortcuts` (hint glyphs are `aria-hidden`).
- Typing filters by case-insensitive substring of the label. The highlight resets to the first match.
- ↑ ↓ move the highlight, clamped at both ends. The highlighted row is scrolled into view.
- ↵ runs the highlighted action. Every listed shortcut also works while the menu is open (⌘↵, ⌘⇧C, and so on).
- Mouse: hover highlights a row (inside the menu, hover does move the highlight, as in Raycast). Click runs it. A click outside the popover closes it.
- Running any action closes the menu first. Focus returns to the search input.
- Panel hide closes the menu. It never reopens on the next show.

### Action feedback (Amends 02 Copy flow, Footer center precedence)

- **Copy and paste actions** (GIF, MP4, square, link, Markdown, page link): the footer center shows the success toast (copy table below), then the panel hides **400 ms** later, as in Phase 2.
- **Open in Browser:** no toast. The browser takes focus and the panel hides (HideOnFocusLost).
- **Download, favorite toggle, remove, Clear Recents, Details:** the panel stays open.
- **Hide timer (fixes 02 IN-07):** a `panel:show` cancels any pending hide-after-copy timer. A re-show within 400 ms never hides again.
- **Toast durations:** copy/paste success → until the panel hides (cleared on next show). `Added to Favorites` → 2 s. Undo toasts and the download toast → 5 s. A later status replaces an earlier one. Undo toasts are **not** cleared by keystrokes or selection changes during their 5 s (removal itself moves the selection). Other transient statuses keep Phase 2's rule (cleared by the next keystroke or selection change).
- **Undo:** one slot, the latest removal only. Undo restores the item(s) at their original position(s) and reselects the restored item. Clear Recents undo restores the whole list.
- **Selection after removal:** the next item in flat order, or the previous one if the removed item was last. If the list becomes empty, the empty state shows.
- **Footer center precedence:** in-flight status (`Copying…`, `Downloading…`, `Cropping…`) → toast (result or error, with optional action) → selected item's title → empty.

### Toast layout (footer center)

`[12px check icon when success] {message}` · 8px · `{action link}` · 4px · `{shortcut hint}`

- Message: 12px Label, tone color (`--success`, `--destructive`, or `--text-secondary`), ellipsized.
- Action link: a `<button>` styled as a text link: 12px Label, `--accent`, no background or border, underline on hover, accent focus ring, `flex: none`. Clicking it runs the action and clears the toast.
- Shortcut hint: 12px Label `--text-tertiary` (`⌘Z`, `⌘R`), `flex: none`.

### Square crop

- Runs in Go at copy time. No preview, no extra UI beyond the busy overlay (after 300 ms) and `Cropping…` in the footer.
- Over 15 MB: refused before any work; footer error row F7. The panel stays open.

### Clips (ACTN-09)

- Clips tiles carry the MP4 badge. ↵ / ⌘↵ copy or paste the 720p MP4 file (nearest available rendition when 720p is missing). The Phase 2 E8 string (`Copying Clips (MP4) arrives in the next update.`) is **retired**.

### Recent searches (SRCH-08)

- Saved per provider: when a GIF from that search is copied or pasted, or after 1.5 s with no typing. Last 20 per provider, no duplicates (a repeat moves to the front). Up to 8 show as chips.
- Library tab filters are never saved as recent searches.
