# Milestones

## v1.0 Gifsmith MVP (Shipped: 2026-10-20)

**Phases completed:** 4 phases, 26 plans, 88 tasks
**Release:** v1.0.0 published 2026-10-20 (https://github.com/scottkw/gifsmith/releases/tag/v1.0.0, tag at ae3d0cd)
**Closeout:** override_closeout. Known verification overrides: 1 newly acknowledged, 0 carried forward from a prior close (see STATE.md Deferred Items); Phase 1 SC5 paste-matrix breadth accepted as 1.0.1 debt

**Key accomplishments:**
- Wails v3 beta.30 + Svelte 5 app at the repo root with the locked identity. ⌃⌥⌘G toggles a non-activating 720×480 NSPanel that takes typing with no click. Enter writes the staged sample GIF to NSPasteboard as a file URL, and ⌘V pastes it animated into TextEdit with Accessibility not granted. The user confirmed this at the tracer gate.
- Gifsmith now has a menu bar tray (Open Gifsmith / Settings… / Quit Gifsmith) that works without the hotkey. The panel opens on the display under the mouse, centered, with its top edge at one sixth of that display's visible height.
- Developer ID-signed, hardened-runtime Gifsmith installs to ~/Applications with one command, ⌘Enter pastes the GIF straight into the previous app when Accessibility is granted (5/5 in TextEdit, plus Notes, Mail, Messages), and a CGO-free server build answers bound calls through the Vite proxy for browser UAT.
- The user recorded GO WITH FALLBACKS for Phase 1 on the Developer ID-signed dev build. The paste matrix now holds the decision, its four limits, and the derived conclusion that one file URL on the pasteboard pastes animated GIFs into TextEdit, Notes, Mail and Messages. The notarized dry run moves to Phase 4 because Apple's notary service returns a 403 for a missing agreement.
- Typing in the panel now searches The Finer Gifs Club from Go (typed, URL-free provider errors through one httpx choke point), renders an animated 4-column grid, and Enter downloads, validates and stages the selected GIF before handing its file URL to the pasteboard; the bundled sample is gone and the smoke script is now the browser UAT harness.
- The result grid is now row-virtualized with @tanstack/svelte-virtual (only about five rows mounted), pages through the provider cursor to "End of results", and is fully keyboard-driven from the search input; the native panel no longer swallows Esc, cannot be destroyed by Cmd+W or cancelOperation, and has only App and Edit menus.
- Every provider call now goes through a Go search.Service that caches pages (trending 10 min, search 5 min), refuses to call a provider during a local 429 block, and dedupes non-Klipy pages. The panel cancels superseded searches through CancellablePromise and renders every UI-SPEC loading, empty, rate-limit and error state from fixed copy rows, never from error text.
- GIPHY (PG-13, offset caps, 50-rune q) and Klipy (path-escaped key, content_filter=medium, results kept as returned) now run from Go. Each client maps its own bad-key statuses. Keys are saved only after a real trending call with the candidate key succeeds. They live in the Keychain (a memory store in the server build), and the verified page is seeded as the first trending result.
- The panel now has the four fixed provider tabs (Cmd+1..Cmd+4, remembered across launches), each with its exact placeholder and vendor attribution (the official GIPHY mark, unmodified). A first run opens on GIPHY with an inline setup card that verifies a key through SettingsService.SaveKey, reports K2/K3/K4 inline, drops into GIPHY trending once the key is saved, re-prompts with K6 when a stored key is rejected, and offers "Try Finer Gifs (no key)".
- GIPHY Clips now appears only when the user's own GIPHY key passes one Clips test call per launch, made after a GIPHY GIFs call with the same key succeeded. Otherwise the C2 card explains how to ask clips@giphy.com for access, and Go refuses Clips calls itself. PROJECT.md records the Phase 2 compliance posture. The user approved the full native UAT on the signed dev build with real keys. Their GIPHY key is not approved for Clips: the probe went `checking -> disabled` and the panel showed C2.
- Link, Markdown and page-link copy, link/Markdown paste and Open in Browser built and validated in Go (cgo NSPasteboard text, onMain NSWorkspace open), driven by Cmd+Shift+C / Cmd+Shift+M / Cmd+O, with typed ActionError kinds and a server UAT build that now runs platform.Fake.
- A Raycast-style ⌘K popover anchored to the selected tile. It lists the selected GIF's actions in the locked order, filters as you type, and runs rows through the same `runAction` dispatcher the shortcuts use. It stays at least 8px inside the window from any column.
- GIPHY Clips now copy and paste their 720p MP4 (or the nearest of 480p, 1080p, 360p) through the same file-URL path as GIFs, with ftyp validation, an MP4 tile badge and MP4 wording. The staging folder now holds at most the clipboard's one file: it is wiped at launch and quit, cleared by text copies, and a pasted Klipy file is deleted 30 s after ⌘V behind a generation guard.
- ⌘S (or the Download GIF / Download MP4 row) now saves the selected item into Downloads as `<title-slug>-<id>.gif` or `.mp4`. The bytes are validated before any file exists, the file is written to a hidden temp file and claimed with `os.Link` under the first free name (` (2)`, ` (3)`…), so nothing is ever overwritten. The 5 s toast offers Show in Finder, by click or ⌘R, which reveals the file Go itself saved.
- Copy Square GIF and Paste Square GIF in the ⌘K menu crop the selected GIF to a center square in Go with stdlib `image/gif`. Frames are cut, not re-encoded through a quantizer, so palettes, delays, loop count and disposal survive. A golden test renders every frame with disposal applied and finds 0 mismatched pixels inside the window. The square file is staged like any copy and the downloaded original is swept. Oversized GIFs are refused before any download (F7), giant canvases before the full decode (F6), and Clips never see the rows.
- Every successful copy or paste now lands in Recents. ⌘⇧F toggles favorites. ⌘5 (Favorites) and ⌘6 (Recents) show the saved metadata grouped by provider, with removal, Clear Recents and a 5 s Undo. Nothing on these tabs calls a provider, so they work offline and while a provider is rate-limited. The lists live in `favorites.json`, `recents.json` and `searches.json` (version 1, mode 0600, written atomically). A file that fails to load is never overwritten.
- ⌘I opens a Details pane built only from the item's own metadata, with Page and Source links that open through Go. An empty search box now shows up to 8 recent-search chips per provider. A search is saved after 1.5 s idle with at least one result, or when a GIF from it is copied. Chips rerun, move and delete from the keyboard. The Phase 2 polish todo and IN-04 are closed, and 14-backstops.js checks contrast, keyboard-only use and long text in light and dark.
- Whole-phase suite green on c814eff (265 Go cases, 63 node tests, SMOKE OK, 18/18 UAT), Developer ID-signed dev build installed, and the user approved the 13-step native UAT; library persistence and ⌘Q staging cleanup lack native evidence on this install and are flagged for the verifier.
- A real Settings window (tray Settings… and Cmd+,) whose General pane sets Theme (NSApp.appearance + data-theme on both pages), Open at login (Wails Autostart with a translocation guard) and shows Automatic paste status, all on a new single-owner settings.Store that fixes the tab-switch overwrite bug.
- Content rating, GIFs per page, GIPHY language and Klipy country are now per-request settings in Go. Changing one flushes only the affected providers' cache and never lifts a 429 block. The Settings window gains a Search pane and a Keys pane that can add, test, change and remove keys, and the webview only ever sees the last 4 characters of a key.
- The global hotkeys can now be rebound from Settings → Hotkeys, and Favorites and Recents get optional hotkeys of their own. Go canonicalises every combo, refuses no-modifier, macOS and duplicate combos, and re-registers the old binding when macOS refuses the new one. Recording suspends Gifsmith's hotkeys, and Test listens 5 s for a real press. The Phase 3 UI-review polish is folded in, and Reduce Motion users see still tiles, with only the selected one animating.
- Downloads now go to a folder the user picks in a native sheet. Go checks the folder before saving it: it refuses exFAT/FAT and network volumes, folders it cannot write to, and any folder where a hard link fails. Downloads can use gifsmith-{id} file names. ↵ and ⌘↵ run actions chosen in Settings. Klipy file actions are refused in Go by a build constant and hidden in the UI. Small, Medium and Large set the panel to 5, 4 or 3 columns, with action-menu placement and right-click to match.
- One command (`wails3 task darwin:release:build`) now produces a Developer ID-signed, hardened-runtime arm64 `Gifsmith.app` and `Gifsmith-1.0.0-arm64.dmg` (new background, LICENSE, checksum), checked by `scripts/verify-release.sh`. `darwin:release` adds notarization and stapling and requires the gifsmith-notary profile, which works. Settings → About credits the Raycast extension's authors, and the README and 1.0.0 release notes cover install, keys, updates, attribution and known limits.
- Gifsmith 1.0.0 is notarized and stapled (app and DMG both Accepted by Apple), passed a clean-machine install in a fresh macOS 15.7.7 VM from the quarantined DMG with only the standard "downloaded from the Internet / Apple checked it" prompt, and now waits as a draft GitHub Release with the DMG and its checksum. The 04-07 updater accepts both the DMG and the draft's release JSON.
- Settings → General → Updates asks GitHub Releases for scottkw/gifsmith (one plain GET with an ETag), alerts through the menu bar and a one-time panel toast, and on request downloads the DMG, checks its SHA-256 digest, Developer ID signature, Team ID and notarization, quarantines it and opens it for the usual drag to Applications. The app never replaces itself.
- CI runs the full suite on macos-15 for every push/PR to main, and a vX.Y.Z tag runs the unchanged `wails3 task darwin:release` on a runner with a temporary Developer ID keychain and notary API key, then drafts the release; proven by a green workflow_dispatch dry run (both notarizations Accepted, RELEASE VERIFY OK (notarized), TestRealDMG PASS) after adding stapler retries.
