## Probe-flagged assumptions

Probes run at planning time (2026-10-18, read-only):
- `GET https://api.github.com/repos/scottkw/gifsmith/releases/latest` → HTTP 404 (repo public via `gh repo view`, no published release yet), `x-ratelimit-remaining: 59`. Hence D-27's "404 = up to date" and the human-check's expected `update: no published release` log line.
- `https://github.com/cli/cli/releases/download/…` → 302 to `https://release-assets.githubusercontent.com/…`. Hence D-31's redirect host list (objects.githubusercontent.com kept for older asset URLs).
- GitHub release asset JSON (cli/cli latest) carries `name`, `size`, `state: uploaded`, `browser_download_url`, `digest: sha256:…`. Hence D-32. If GitHub drops `digest`, updates fail closed (U-E3) and the user downloads manually; 04-06's TestReleaseJSON catches it before 1.0.0 is published.
- Wails beta.30 `MenuItem.SetHidden` / `SetLabel` dispatch to the main queue themselves (menuitem_darwin.go); `App.Context()` exists.
- RELS-05 (unclassified): GitHub's unauthenticated limit is per IP; on a shared NAT the check can hit 403. That is logged and, for a manual check, shows U-E1; it never blocks the app.
- RELS-06 (unclassified, unresolved): the spctl open-context assessment of a stapled DMG is expected to print `accepted` + `source=Notarized Developer ID` offline; proven only by 04-06 running TestRealDMG on the notarized artefact. A byte-flipped DMG is expected to fail `codesign --verify --strict`; same proof point.
- Shortcut (D-33, recorded): the app inside the DMG is not mounted and re-verified; the DMG signature, its notarization and the quarantine attribute (Gatekeeper at first launch) cover it.
- Not verifiable before a release newer than 1.0.0 exists: the full in-app download → open on the real endpoint and the tray item's rendering. Every component is verified separately (fixture UAT, TestRealDMG, TestReleaseJSON, the signed-install 404 check); the 04-06 SUMMARY tells the user to try Check for Updates… on 1.0.0 when 1.0.1 ships.
